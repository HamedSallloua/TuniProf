Also on the host:

- [ ] **Daily scheduler** calling `POST /api/jobs/daily` once a day with the header `Authorization: Bearer <CRON_SECRET>` (spec 8.1, M4). **Careful:** the route accepts POST only, and some hosts' schedulers (Vercel Cron, to my knowledge) call with GET and send the secret in the same header. ## 4. Database and settings on the production server

The production database starts **empty**: nothing from your development database is copied.

Order of the first deployment (exact commands are given when we get there, M12):

1. [ ] `npm run db:migrate`, which creates every table, the catalogues (24 governorates, levels, subjects, plans) and the default settings. Never use `db:reset` there (it refuses production, on purpose).
2. [ ] `npm run db:import:delegations` **once** (279 délégations from `db/data/delegations.csv`). Running it again overwrites names.
3. [ ] `npm run admin:create -- --role=admin_super` (you type the phone and a hidden password, so only you know it). Then an admin with the `admin_support` role if needed.
4. [ ] Replace the **placeholders in the `settings` table**. Until the admin settings screen exists (M11), do it with SQL in `psql`. Values are JSON: text in double quotes inside single quotes, `true` without quotes. Example:

```sql
UPDATE settings SET value = '"Nom du bénéficiaire"' WHERE key = 'payment.beneficiary_name';
UPDATE settings SET value = 'true' WHERE key = 'payment.configured';
```

| Key                                                                                                                    | What                                                                                                                                            | Placeholder now                    |
| ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| `payment.beneficiary_name`, `payment.flouci_number`, `payment.d17_info`, `payment.ccp_number`, `payment.working_hours` | Payment details shown to teachers                                                                                                               | "PLACEHOLDER - ..."                |
| `payment.whatsapp_number` (digits with country code), `payment.messenger_page`                                         | Where teachers send the proof                                                                                                                   | `00000000000`, `placeholder-page`  |
| `payment.helper_lines_ar`                                                                                              | The Arabic helper lines, as a JSON list of texts                                                                                                | `[]`                               |
| `payment.configured`                                                                                                   | **Switch**: `true` only when all the above are real. While `false`, production hides the payment pages and nobody can create a payment request. | `false`                            |
| `contact.email`, `contact.configured`                                                                                  | Contact page                                                                                                                                    | `contact@example.invalid`, `false` |
| `founding.slots_total`, `founding.days`, `founding.grant_visibility`, `founding.grant_dashboard`                       | Founding offer (100 places, 365 days)                                                                                                           | 100, 365, true, true               |
| `founding.slots_used`                                                                                                  | Must be `0` at launch                                                                                                                           | 0                                  |
| `codes.expiry_days`                                                                                                    | Life of an unused activation code                                                                                                               | 90                                 |
| `profile.rate_min_millimes`, `profile.rate_max_millimes`                                                               | Hourly rate limits (5 to 300 DT)                                                                                                                | 5000, 300000                       |

5. [ ] Check that the **plans and prices** in the `plans` table match spec 2.1 (Mensuel 15 / 25, Trimestriel 40.5 / 65, Semestriel 72 / 111, Annuel 120 / 180 DT).
6. [ ] Check the database time zone and that dates behave (sessions are stored as local date and time with no time zone; plan dates are exact instants; the app computes "now" in Africa/Tunis). M8 tested this with fixed dates; do one real check on the production database (create a session for today, see that it is locked only after its end time).
7. [ ] **Never** run `npm run dev:sample-teachers` on production. It refuses any database that does not end with `_dev`; keep it that way. Remove the sample teachers from your development database whenever you like (`npm run dev:sample-teachers -- --remove`).

## 9. Choices I made that you may want to change

Not in the spec. Each is recorded with its reason in `docs/DECISIONS.md`. None blocks launch, but please look at them once.

- Bio rule: a bio mentioning WhatsApp, Facebook, Instagram, Telegram, TikTok, Snapchat, Messenger or Viber is refused (besides phone numbers, links, e-mails and @handles). Open since M3: confirm it is not too strict.
- Password rules (8 to 128 characters, not containing the phone number), session lifetimes (teacher 30 days, reviewer 24 hours, admin 12 hours), and the numbers of the rate limits (M2).
- Upgrade price of the Dashboard mid-term (my formula, easy to change in `lib/billing/plans.ts`) (M4).
- Ranking weights (40 completeness, 40 rating, 20 renewal), the one-hour rotation, 20 results per page (M5).
- Reveal limit per network address (300 per hour) and the four report reasons (M5).
- Featured cities and subjects on the home page (M5).
- Landing pages with nobody living in the city are `noindex` (M5).
- Reviews (M6): no editing or deleting of one's own review in v1, and a refused review still blocks a new one by the same account on that teacher (one review per account and teacher, as the spec says); at most 3 reviews per rolling 24 hours; a teacher's reply is public at once, one only, final; the review comment and the reply have no contact-detail filter; the four review states (new, published, refused, hidden); the three reasons a teacher can give when reporting a review (M6).
- Dashboard (M8): no archiving of groups (removed at the owner's request); a session of today that is already over is not created; there is no school-year shortcut; "Supprimer" a session is permanent and a session deleted one by one is created again if "Modifier calendrier" rebuilds the future with a pattern that includes it; past sessions are locked in the application, not in the database; 10 group colours picked automatically; a group can be deleted only by typing its name; a moved session keeps its first original date; the Dashboard menu shows only the sections that exist; "Ajouter une séance" accepts at most 50 rows at once; a day deleted or edited in the group wizard is created again if "Modifier calendrier" rebuilds with a pattern that includes it, while days added by hand are never touched by it.
- Notifications (M7): approvals, refusals and payment events go to WhatsApp (copy-paste) AND the on-site notice, plus e-mail when an address exists (the spec says "WhatsApp or e-mail"); reminders at 30, 7 and 1 day, only the smallest that applies is sent; the end-of-grace warning is sent 7 days before the 30 read-only days end; e-mails are French then Arabic in one message (the language of a teacher is not stored); retention periods of the cleanup (rate limits 2 days, webhooks 30 days, challenges and sessions 30 days, notifications 12 months); an e-mail is tried 3 times; a payment refusal tells the teacher only the reference (the admin's note stays internal).
